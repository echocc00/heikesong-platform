# 三端拆分 · 目标对齐与差距分析

> **日期**：2026-10-22
> **触发**：用户指出现有页面「要优化的内容非常多」，要求把**用户端 / 管理员端 / 组委会端**三个系统分开，
> 并先搞清楚「是目标偏了，还是开发过程中有问题」。
> **结论先行**：**两者都不是。后端没偏、需求没偏、也没走偏 —— 是前端从未按角色分区做过界面。**
> 全部数字均可复算（命令见文末 §6）。

## 0. 一句话结论

| 问 | 答 | 硬证据 |
|---|---|---|
| 目标偏了吗？ | **没偏。** 96 条需求全部有交代（**95** 条已落地 + **1** 条按溯源表声明平台不实现） | `docs/requirement-implementation-map.md` |
| 开发走偏了吗？ | **没走偏。** 后端 57 个端点、20 个能力点、7 个角色、45 条角色授权**全都按设计做出来了** | 真机数据库 + `platform/src/` |
| 那问题在哪？ | **前端 1067 行 / 11 个视图，只消费了后端 11 个端点 —— 46 个端点（81%）没有任何界面入口** | `platform/web/` vs `platform/src/http/routes/` |

> 一句话：**地基（权限/能力/规则引擎/数据模型）打得很扎实，房子只盖了一层毛坯，而且所有住户共用一个大门。**

## 4. 判断：目标偏了，还是开发有问题？

### 4.1 逐项对照

| 维度 | 材料/你期望的 | 实际做的 | 判断 |
|---|---|---|---|
| 需求覆盖 | 96 条 | **96 条全部有交代**：95 ✅ 已落地 + 1 ⚪ 平台不实现（溯源表已声明不实现，非缺口） | ✅ **没偏** |
| 后端能力 | 规则可配、权限可分轨、可复算 | 20 能力点 + 7 角色 + 45 授权 + 46 端点 | ✅ **没走偏** |
| 规则引擎 | 机制件配置化 | `rules/*.json` 16 份 + 纯函数引擎 + trace | ✅ **超额完成** |
| 三端拆分 | 三个独立系统 | **一个系统、6 个平铺入口** | ❌ **前端完全没做** |
| 页面数量 | 按角色覆盖 | 11 个视图覆盖 11/57 端点 | ❌ **前端欠 81%** |
| 视觉/交互 | 生产级 | 演示级（截图实测：榜单页只有标题 + 「暂无数据」） | ❌ **前端欠打磨** |

### 4.2 为什么会出现这个差距（根因）

**P0–P6 六个阶段的验收标准全部锁在「后端行为」上** —— 需求落地表的「怎么验」一列，96 条**全部指向 P0–P6 的后端验收标准**（无一条指向前端）。

⇒ 结果：**后端被验收得很严，前端从来没被验收过。**
⇒ 没人给前端定验收标准 ⇒ 前端就停在「能跑通一个 Demo」的规模。

> 这不是执行失误，是**计划本身的结构性缺口**：
> 「报名/榜单/评审 Demo」这个原始任务包要求（P0 计划 §1.1 源头①），
> 被我方转述成了「**评审引擎**要准」，而**「评审界面」没人写**。
> 引擎做得越精确，界面越显空 —— 现在后端 13 827 行 vs 前端 1 067 行。

### 4.3 三条可复用的结论

1. **地基没白打** —— 三端拆分**不需要重写后端**，权限模型已经是三端形态。
2. **补前端比补后端便宜** —— 46 个端点已就位，前端只需消费。
3. **下一轮计划必须给前端定验收标准** —— 否则下一轮还会是"后端更厚、前端更薄"。

## 8. P7 落地进展（2026-10-22 · 「现有页面打磨到生产级」）

本文第 2 节的结论「**前端从未按角色分区做过界面**」已在 P7 落地第一版：

| 本文结论 | P7 的处置 | 证据 |
|---|---|---|
| 导航是 6 个平铺链接，所有人一样 | **导航按角色分区**（`web/nav.js`，声明式数据）：赛事（公开）/ 我的赛事（需登录）/ 组委会（`admin`，超管直通） | `platform/test/web-ui.test.js` 6 条 |
| 前端路由守卫缺失，未登录点「报名」渲染出一个必然 401 的表单 | 路由守卫**只判登录态** ⇒ 未登录直接给「需要登录」引导页（⛔ 不按角色拦 —— 授权归 API） | `web-ui.test.js` 2 条（含反向对照） |
| `styles.css` 36 行 / 8 个变量 | **设计系统** 649 行：token + 组件 + 状态三件套 + 响应式 + 亮暗双主题 | class 清单差集核对（0 缺失） |
| 11 个视图各写各的空态/错误态 | 统一到 `web/ui.js` 的**纯函数**外壳三件套 | `web-ui.test.js` 32 条 |
| 「赛段榜没有赛段可选」「任务清单页不可达」 | 补 `GET /api/stages`、`GET /api/workflows` 两个只读端点 + 新增工作流索引页 `/tasks` | `web/api.demo.js` 与真实后端同形状 |
| 演示站六页 404（端点缺失） | 演示适配器补齐 8 个端点 + 专属错误码 `DEMO_ENDPOINT_MISSING` + 端点覆盖回归闸 | `platform/test/demo-api-parity.test.js` 7 条 |

**仍然没解决**（下一轮 P8）：**46 个端点里剩下的评审与发榜链路仍无界面入口** ⇒ 无人能打分、无人能发榜 ⇒ 赛事还跑不起来。
⇒ P8 的范围（已定）：**「评审打分页」+「赛段计算发榜页」** = 赛事能跑起来的最小闭环。

### 8.1 P7.1 收尾：真实浏览器里抓到的 5 个 bug（2026-10-22）

P7 的验收全是「测试绿 + 机器闸绿」，而下面 5 个缺陷**全部通过了这些闸** —— 它们是在**真实浏览器**里点出来的：

| # | 现象 | 为什么机器闸抓不到 | 处置 |
|---|---|---|---|
| B1 | 未登录时首页「参赛队伍」显示的是**榜单数** | 判据是「页面上有这几个字」，不是「数字对不对」 | 抽纯函数 `homeKpiCards` + 标签跟着值出现/消失 |
| B2 | 榜单每行是「. 拾光队」+「分」 | 同上（字段存在但值为空，页面不报错） | 名次按序自己编号、积分取 `points`（真实字段） |
| B3 | 错误态「重试」点了没反应 | 只断言了**按钮存在**，没断言**click 被绑定** | 抽可重入的 `loadBoard()` + 结构闸断言 `addEventListener('click'` |
| B4 | 「报名入口」点了是「页面不存在」 | 死链**不崩溃**，只是一段没人点的 HTML | **死链闸**：路由表 vs 所有 href 逐一比对 |
| B5 | 网络失败把英文 `Failed to fetch` 甩给用户；且**一次失败后演示站永久瘫痪** | 失败路径**没被测过**（测试环境网络永远通） | 失败**不缓存** + `friendlyError()` 放在 `errorState()` 唯一出口 |

⇒ **结论（与本文第 4.2 节同源）**：验收只覆盖「已写出来的正常路径」⇒ 口径错、字段错、链接错、失败路径错**全都测不出来**。
⇒ **补法**：① 把可断言的口径抽成**纯函数**；② 给「链接 / 失败 / 字段优先级」各补一条**机器闸**；③ **真机点一遍**仍是最后一道闸。

### 8.2 P8 落地：评审打分页 + 赛段计算发榜页（2026-10-22 · 最小闭环）

**侦察结论（与直觉相反，值得记一笔）**：赛事跑不起来**不是后端缺功能**。
评审打分（`POST /reviews`）、赛段计算（`POST /compute`）、计算留痕（`GET /audit/computations/:id`）
这些链路 **P2/P3/P4 早就全部实现** ⇒ **46 个端点里没有一条缺实现**，缺的**只是界面入口**。

⇒ 所以 P8 的主体是前端；后端只补**一个读口**（`GET /api/stages/:stageId/review-board`：
名册 + 维度 + 我已给的分 + 进度，一次拿齐，避免前端拼三个请求还拼错口径）。

| 页面 | 谁用 | 做什么 |
|---|---|---|
| `#/review/:stageId` | 评委 / 企业席 / 组委会 | 逐维度 **0–100** 打分 → 提交（可改，改分留审计痕） |
| `#/publish/:stageId` | 组委会 | 发榜前检查 → **二次确认** → 计算并发榜 → 结果 + 告警 + 留痕链接 |

**三端归属**（本文 §3 的划分在 P8 落地后的样子）：

- **用户端**：报名 / 我的战队 / 任务清单 / 榜单 / 段位榜（P1/P3/P5/P7 已落地）
- **管理员端（评委席）**：**评审打分**（P8 新增）⇒ 「管理员端」不再是空的
- **组委会端**：报名筛选台 / 复核队列 / **赛段发榜** / 计算留痕 / 申诉（P1/P4/P8 落地）

⇒ **一条完整链路现在可以走通**：报名 → 组队 → 领任务 → （评委）打分 → （组委会）计算发榜 → 榜单 → 段位 → 战绩卡。

**仍然没做**（下一轮）：企业确认双签页 / 自评提交页 / 互评页 / 回避申报页 / 校准打分页 / 申诉受理页
（P2/P4 后端都有，前端未做）；三池可视化；赛程日历。
